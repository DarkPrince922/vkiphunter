# Установка VK IP Hunter с нуля

Полный путь: от регистрации в VK Cloud до работающей службы на сервере.
Каждый шаг проверяем сразу — так ошибка находится там, где возникла, а не
через час.

Что получится в итоге: бот в Telegram, который сам ждёт освобождения
публичного IPv4 в нужном пуле VK Cloud, круглосуточно, без вашего участия
и без открытой консоли.

## 1. Аккаунт VK Cloud и 2FA

1. Зарегистрируйтесь в VK Cloud (`cloud.vk.com`) — понадобится подтверждение
   телефона и карта для активации платных ресурсов.
2. Включите двухфакторную аутентификацию: раздел профиля/безопасности в
   личном кабинете, пункт про двухфакторную аутентификацию или 2FA.
   Приложение — любой TOTP-клиент: Google Authenticator, Aegis, 1Password.
3. **Сохраните резервные коды** в менеджер паролей. Без них потеря телефона
   означает потерю доступа к проекту вместе со всеми пойманными адресами.

> 2FA защищает личный кабинет. Бот в кабинет не ходит — он работает через
> OpenStack API по отдельным доступам, которые мы получим на шаге 2.
> Поэтому 2FA ему не мешает.

## 2. Проект и доступ к OpenStack API

### 2.1. Проект

В личном кабинете должен быть проект — он же tenant в терминах OpenStack.
Обычно создаётся автоматически при регистрации, имя вида `mcs6434280924`.
Запомните его: оно понадобится для проверки, что бот подключился именно
туда, куда нужно.

### 2.2. OpenRC-файл

В настройках проекта найдите раздел с доступом к API — обычно называется
«OpenStack RC файл», «Ключи доступа» или «API-доступ». Скачайте файл,
он выглядит так:

```bash
export OS_AUTH_URL=https://infra.mail.ru:35357/v3/
export OS_PROJECT_ID=d48dc24102414d67877a4bcbf58bf711
export OS_PROJECT_NAME="mcs6434280924"
export OS_USER_DOMAIN_NAME="users"
export OS_USERNAME="you@example.com"
export OS_REGION_NAME="RegionOne"
```

Пароля в файле нет — он спрашивается при запуске. Это нормально.

Содержимое этого файла вы просто пришлёте боту сообщением на шаге 8 —
разбирать его вручную не нужно.

### 2.3. Квоты

Проверьте квоту на порты и floating IP в личном кабинете. Каждая
параллельная попытка занимает один адрес, поэтому при квоте, скажем, 10
адресов больше 2–3 воркеров ставить не стоит.

## 3. Сервер: пользователь, ключи, firewall

Подойдёт любая VPS с Debian 12 или Ubuntu 22.04/24.04, 1 vCPU и 1 ГБ RAM
хватает с запасом. Бот почти ничего не потребляет: одна попытка раз в
несколько десятков секунд.

### 3.1. Первый вход

```bash
ssh root@ВАШ_СЕРВЕР
```

### 3.2. Обновление и часовой пояс

```bash
apt update && apt -y upgrade
timedatectl set-timezone Europe/Moscow
```

Часовой пояс важен: время в логах и в сообщениях бота будет вашим.

### 3.3. Отдельный пользователь

Работать под `root` не нужно — бот прекрасно живёт под обычным
пользователем.

```bash
adduser vkiphunter          # спросит пароль и ФИО, ФИО можно пропустить
usermod -aG sudo vkiphunter
```

### 3.4. SSH-ключ

**На своей машине** (не на сервере) создайте ключ, если его ещё нет:

```bash
ssh-keygen -t ed25519 -C "vkiphunter"
ssh-copy-id vkiphunter@ВАШ_СЕРВЕР
```

Проверьте, что вход по ключу работает, **не закрывая текущую сессию**:

```bash
ssh vkiphunter@ВАШ_СЕРВЕР
```

### 3.5. Запрет входа по паролю

Только после того, как вход по ключу подтверждён:

```bash
sudo nano /etc/ssh/sshd_config
```

```
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
```

```bash
sudo systemctl restart ssh
```

> Держите вторую SSH-сессию открытой, пока не проверите новый вход. Если
> что-то сломается, у вас останется рабочее подключение.

### 3.6. Firewall

```bash
sudo apt -y install ufw
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status
```

Бот не принимает входящие соединения — он сам ходит в Telegram и в VK
Cloud. Открывать ему порты не нужно.

### 3.7. Защита от перебора

```bash
sudo apt -y install fail2ban
sudo systemctl enable --now fail2ban
```

## 4. Двухфакторный вход по SSH (по желанию)

Если хотите TOTP-код в дополнение к ключу.

```bash
sudo apt -y install libpam-google-authenticator
google-authenticator
```

На вопросы отвечайте: токены по времени — `y`, обновить файл — `y`,
запретить повторное использование — `y`, расширенное окно — `n`,
ограничение частоты — `y`. **Сохраните резервные коды.**

```bash
sudo nano /etc/pam.d/sshd
```

Добавьте первой строкой:

```
auth required pam_google_authenticator.so
```

```bash
sudo nano /etc/ssh/sshd_config
```

```
KbdInteractiveAuthentication yes
AuthenticationMethods publickey,keyboard-interactive
```

```bash
sudo systemctl restart ssh
```

> Проверяйте вход из **новой** сессии, не закрывая текущую. Ошибка в этой
> настройке запирает сервер снаружи.

## 5. Telegram-бот у BotFather

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot` → имя (любое) → username (обязательно заканчивается на `bot`).
3. Скопируйте токен вида `123456789:AAE...`.

Токен — это полный доступ к боту. Никому не пересылайте; если утёк,
`/token` у BotFather выдаст новый.

Свой Telegram ID узнавать заранее не нужно: бот определит его сам на
шаге 7.

## 6. Установка бота

Под пользователем `vkiphunter`:

```bash
sudo apt -y install git python3 python3-venv
sudo mkdir -p /opt/vkiphunter
sudo chown vkiphunter:vkiphunter /opt/vkiphunter

git clone -b claude/new-project-fd3wg2 \
    https://github.com/DarkPrince922/vkiphunter.git /opt/vkiphunter
cd /opt/vkiphunter
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
```

Проверка, что всё встало:

```bash
.venv/bin/python -m pytest -q
```

Ожидается `101 passed`.

## 7. Первый запуск и владение ботом

```bash
cd /opt/vkiphunter && .venv/bin/python -m vkiphunter
```

Бот спросит токен и сохранит его в `data/credentials.json` с правами
`0600`. Больше терминал для настройки не понадобится.

Теперь в Telegram найдите своего бота и отправьте:

```
/start
```

Первый, кто это сделал, становится владельцем — его ID сохраняется, и
посторонние бота уже не получат. Бот ответит «👑 Вы владелец этого бота»
и покажет меню.

> Если бот молчит — смотрите терминал, причина написана там.

## 8. Подключение VK Cloud

В боте: **«☁️ Подключить VK Cloud»** или команда `/connect`.

Самый быстрый путь — **«📋 Вставить openrc-файл»**:

1. Откройте скачанный на шаге 2 файл и скопируйте его содержимое целиком.
2. Отправьте боту одним сообщением.
3. Бот разберёт файл и покажет, что понял: пользователя, проект, регион.
4. Пришлите пароль от VK Cloud — сообщение с ним бот удалит из чата сразу
   после прочтения.

Доступы проверяются живым запросом к API и сохраняются, **только если
подошли**. При ошибке ничего не запишется, а бот скажет, что именно не так.

Альтернатива для постоянной работы — application credential: он не зависит
от смены пароля аккаунта. Создаётся так:

```bash
sudo apt -y install python3-openstackclient
source ~/mcsXXXXXXXXX-openrc.sh
openstack application credential create vkiphunter
```

Полученные `id` и `secret` введите в `/connect` → «🎫 Application credential».

Проверка: `/cloud` — должен показать проект, пользователя, регион и ID
внешней сети.

Когда увидите «✅ Облако подключено», нажмите `Ctrl+C` в терминале.

## 9. Автозапуск через systemd

```bash
sudo cp /opt/vkiphunter/scripts/vkiphunter.service /etc/systemd/system/
```

Если ставили под отдельным пользователем — раскомментируйте в файле
строки `User=` и `Group=`:

```bash
sudo sed -i 's/^#User=/User=/; s/^#Group=/Group=/' /etc/systemd/system/vkiphunter.service
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now vkiphunter
sudo systemctl status vkiphunter --no-pager
```

Служба поднимается после падения и после перезагрузки сервера. Дальше
перезапуск всегда так:

```bash
sudo systemctl restart vkiphunter
```

## 10. Настройка охоты

Всё делается в боте, порядок важен.

### 10.1. Способ добычи адреса

`/settings` → **«🧭 Способ»**:

| Способ | Что создаётся | Что делать с найденным |
| --- | --- | --- |
| порт во внешней сети *(по умолчанию)* | порт в сети `internet` | стать интерфейсом новой ВМ (`/vm`) |
| floating IP | обычный floating IP | привязать к существующей ВМ (`/attach`) |

Исторически рабочий адрес `217.16.22.90` был получен **портом**, а не
floating IP. Пулы у этих двух способов могут отличаться — если один не
даёт целевых адресов, попробуйте второй.

### 10.2. Целевые диапазоны

`/targets` — по умолчанию стоят исторические:

```
5.188.140.0/22
217.16.16.0/21
217.16.24.0/22
217.16.28.0/22
```

Кнопка **«📋 Все диапазоны VK»** добавляет 31 публичный диапазон VK разом —
это шире исторического списка и покрывает его целиком.

Меняли цели — обновите подсети: бот сам об этом напомнит и даст кнопку
**«🗺 Подсети под эти цели»**. Старый выбор подсетей под новый список
целей не подходит.

Свои диапазоны можно вставлять списком: через запятую, пробелы или с новой
строки. Бот разберёт сообщение целиком, отбросит дубликаты и свернёт
вложенные подсети.

Проверка идёт математикой CIDR, а не по префиксу строки. Исключения
приоритетнее целей.

### 10.3. Где вообще есть нужные адреса

`/networks` — внешние сети проекта и их пулы. Целевые помечены 🎯.

Если ни одна подсеть не пересекается с целями, бот скажет это прямо:
таких адресов проекту не выдают, и ждать бесполезно.

### 10.4. Выбор подсетей — самый важный шаг

`/subnets` → **«🎯 Все подходящие»**.

Без этого шага Neutron выдаёт адрес из того пула, где сейчас есть
свободные, — обычно из чужого. Попросить адрес «из CIDR 217.16.16.0/21»
в API нельзя: выделение идёт из объекта subnet, поэтому нужную подсеть
надо выбрать явно.

С выбранными подсетями `409 No more IP addresses available` означает
именно «в этом пуле сейчас пусто» — и вот тогда ожидание работает.

### 10.5. Воркеры и интервал

`/settings`:

- **Воркеров** — сколько адресов пробовать одновременно (1–8). Воркеры
  раскладываются по выбранным подсетям: четыре воркера на четыре
  подсети — каждый в своей.
- **Интервал** — пауза между попытками одного воркера, по умолчанию 90 с.

Начните с 1–2 воркеров. Каждый держит по адресу, а квота не резиновая:
при её исчерпании облако ответит `Quota exceeded`, и бот об этом скажет
отдельным сообщением.

### 10.6. Запуск

`/hunt` — или кнопка «▶️ Запустить охоту».

Перед стартом бот проверяет доступ к облаку и наличие сети, так что
цикл не будет крутиться вхолостую.

## 11. Наблюдение

### В боте

| Команда | Что показывает |
| --- | --- |
| `/status` | попытки за запуск, 409, ошибки, время работы, следующая попытка |
| `/history` | последние 20 попыток: воркер, адрес, подсеть, причина |
| `/ips` | какие адреса уже выдавались и сколько раз |
| `/availability` | сколько свободных адресов в каждом пуле |
| `/ports` | выданные ресурсы: свои отдельно от чужих |
| `/log` | последние строки лога прямо в чате |
| `/debug` | подробный лог: запросы к VK Cloud и ответы API целиком |

Живой статус обновляется на каждой попытке в одном сообщении — чат не
забивается. Отдельно приходят только старт, сводка раз в N попыток и
находка.

### В терминале

```bash
journalctl -u vkiphunter -f                        # всё живьём
journalctl -u vkiphunter -f | grep воркер          # только попытки
tail -f /opt/vkiphunter/data/vkiphunter.log        # тот же лог файлом
grep -E "409|ERROR" /opt/vkiphunter/data/vkiphunter.log | tail -30
```

Строка попытки:

```
воркер 0 · mcs6434280924 / you@example.com · подсети 217.16.16.0/20 · 217.16.19.112 · входит в 217.16.16.0/21
```

## 12. Когда адрес найден

Бот пришлёт уведомление и **остановит охоту**. Найденный ресурс не
освобождается никогда — ни при остановке, ни при ошибке, ни при уборке.

### Режим порта

`/vm` — мастер из четырёх шагов: флейвор → образ → SSH-ключ →
подтверждение. По умолчанию отфильтрованы 1 vCPU / 2 ГБ и Ubuntu 24.04,
диск 10 ГБ. Машина создаётся с подключением именно к найденному порту.

### Режим floating IP

`/attach` — выбираете ВМ из списка проекта, бот сам находит её внутренний
порт и вешает адрес на него.

### Проверка, ради которой всё затевалось

Попадание в целевой CIDR — **только предварительный фильтр**. Он не
доказывает, что мобильный оператор пропускает адрес. Реальная проверка:

1. открыть нужный порт в security group и в firewall самой ВМ;
2. поднять простой health-endpoint;
3. убедиться, что он отвечает из обычного интернета;
4. на телефоне **выключить Wi-Fi**;
5. повторить запрос через целевую SIM и APN.

```bash
curl -4v --connect-timeout 8 http://НОВЫЙ_IP/health
```

| Обычный интернет | Ограниченная сеть | Вывод |
| --- | --- | --- |
| не работает | не работает | чинить сервер, firewall или security group |
| работает | не работает | адрес не проходит белый список оператора |
| работает | работает | адрес — рабочий кандидат для этой SIM на момент теста |

`whois`, ASN и совпадение CIDR сетевой тест не заменяют.

## 13. Обслуживание

### Обновление

```bash
cd /opt/vkiphunter
git pull
.venv/bin/pip install -r requirements.txt
sudo systemctl restart vkiphunter
```

Настройки, найденные адреса и доступы лежат в `data/` и переживают
обновление.

### Резервная копия

```bash
tar czf ~/vkiphunter-backup-$(date +%F).tar.gz -C /opt/vkiphunter data
```

В `data/credentials.json` лежит пароль от облака — храните копию так же
бережно, как сам пароль.

### Уборка

После долгой охоты проверьте, не остались ли пробные ресурсы:

```
/ports
```

Кнопка уборки удалит только свои (по префиксу имени или описания),
пропустив найденные и занятые. Чужие ресурсы бот не трогает никогда.

### Расход

Помните, что удерживаемые адреса и созданные ВМ влияют на квоту и
тарификацию. Лишний найденный адрес освободите вручную, когда решите,
какой оставить.

## 14. Если что-то не работает

| Симптом | Причина и что делать |
| --- | --- |
| Бот молчит на `/start` | Процесс не запущен: `systemctl status vkiphunter`, затем `journalctl -u vkiphunter -n 50` |
| «Доступ запрещён» со своим ID | Владельцем стал другой аккаунт. ID владельца в `data/credentials.json`, поправьте и перезапустите |
| «Облако не подключено» | Пройдите `/connect` заново |
| `401 Unauthorized` при подключении | Неверный пароль или протухший application credential |
| «не достучаться до Keystone» | Неверный `OS_AUTH_URL` или нет сети с сервера |
| Приходят адреса не из целевых пулов | Не выбраны подсети: `/subnets` → «Все подходящие» |
| Сплошные `409` | Целевые пулы заполнены. Это штатное ожидание — проверьте `/availability` и оставьте охоту работать |
| `Quota exceeded` | Уменьшите число воркеров, освободите лишние адреса через `/ports` |
| Непонятная ошибка API | `/debug`, повторите действие, посмотрите `/log`, затем выключите `/debug` обратно |
