# Установка веб-версии VK IP Hunter с нуля

Инструкция для **чистого Ubuntu Server 24.04 LTS или Debian 12**, с systemd,
публичным IP, SSH и правами root. На других дистрибутивах имена пакетов и
настройки Nginx могут отличаться. Минимальный практический ориентир: 1 vCPU,
1 ГБ RAM, несколько ГБ свободного диска. Для реального поиска нужен отдельный
проект VK Cloud с квотой на публичные адреса и исходящим доступом к его API.

Результат: браузерная панель на `http://IP_СЕРВЕРА`, защищённая паролем,
Nginx на порту 80, Python-приложение на `127.0.0.1:8080`, автозапуск systemd.
Telegram и токен бота не нужны. Команды ниже выполняются **на сервере от root**,
если явно не сказано иначе. IP и домены в примерах заменяйте своими.

Обычный HTTP **не шифрует пароль панели, cookie и доступы к облаку**.
Для интернета рекомендуется HTTPS (раздел 10) или SSH-туннель (раздел 9).
Сам поиск создаёт облачные ресурсы, которые могут тарифицироваться.

## 1. Вход и подготовка сервера

На своём компьютере:

```bash
ssh root@IP_СЕРВЕРА
```

На сервере:

```bash
apt update
apt upgrade -y
apt install -y git ca-certificates python3 python3-venv python3-pip nginx ufw curl openssl nano
adduser --system --group --home /opt/vkiphunter --no-create-home vkiphunter
```

Если `adduser` сообщает, что такой пользователь уже есть, проверьте его через
`id vkiphunter`; повторно создавать пользователя не нужно.
Если сервер после обновления требует перезагрузки, выполните `reboot` и
подключитесь по SSH снова перед продолжением.

## 2. Получить исходники

Репозиторий приватный: аккаунт GitHub должен иметь к нему доступ.
Создайте fine-grained Personal Access Token с доступом **Contents: Read-only**
к `DarkPrince922/vkiphunter` либо настройте SSH deploy key с чтением.
При HTTPS-клонировании Git спросит имя пользователя GitHub и пароль:
в качестве пароля вставьте **токен**, обычный пароль GitHub не подходит.
Не вставляйте токен в URL и команды: он попадёт в историю терминала.

До слияния PR используйте ветку веб-версии:

```bash
git clone --branch codex/http-web-panel https://github.com/DarkPrince922/vkiphunter.git /opt/vkiphunter
cd /opt/vkiphunter
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
install -d -o vkiphunter -g vkiphunter -m 0700 /opt/vkiphunter/data
```

После слияния PR можно клонировать основную ветку без `--branch`.
Исходники и `.venv` могут принадлежать root; службе нужно записывать только
в `data/`. Не запускайте бота и веб-панель одновременно с одной папкой `data/`.

Если используете SSH, команда клонирования вместо HTTPS:

```bash
git clone --branch codex/http-web-panel git@github.com:DarkPrince922/vkiphunter.git /opt/vkiphunter
```

## 3. Пароль и конфигурация

Создайте минимальный `.env` со случайным паролем. В этой конфигурации доступы
к VK Cloud вводятся затем через браузер.

```bash
cd /opt/vkiphunter
umask 077
.venv/bin/python - <<'PY'
from pathlib import Path
import secrets
p = Path('.env')
if p.exists():
    raise SystemExit('.env уже существует; отредактируйте его вручную, чтобы не потерять настройки')
p.write_text(
    'WEB_HOST=127.0.0.1\n'
    'WEB_PORT=8080\n'
    f'WEB_PASSWORD={secrets.token_urlsafe(32)}\n'
    'WEB_SECURE_COOKIE=false\n'
    'STATE_FILE=data/state.json\n'
    'CREDENTIALS_FILE=data/credentials.json\n'
    'LOG_FILE=data/vkiphunter.log\n'
    'LOG_LEVEL=INFO\n'
)
PY
chown root:vkiphunter .env
chmod 0640 .env
```

Посмотреть пароль для первого входа:

```bash
sed -n 's/^WEB_PASSWORD=//p' /opt/vkiphunter/.env
```

Сохраните его в менеджере паролей. Если задаёте свой пароль, нужно не менее
16 символов. Для изменения: `nano /opt/vkiphunter/.env`, затем
`systemctl restart vkiphunter-web`. Все веб-сессии после перезапуска сбрасываются.

`WEB_HOST=127.0.0.1` оставляет Python-порт доступным только локально;
браузер подключается через Nginx. Не открывайте 8080 в firewall без необходимости.
`WEB_SECURE_COOKIE=false` требуется для HTTP; для HTTPS включите `true`.

## 4. Запустить службу

```bash
cd /opt/vkiphunter
cp scripts/vkiphunter-web.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now vkiphunter-web
systemctl status vkiphunter-web --no-pager
curl -fsS http://127.0.0.1:8080/healthz
```

Ожидается `{"ok": true}`. Если служба не запустилась:

```bash
journalctl -u vkiphunter-web -n 100 --no-pager
```

Служба работает от `vkiphunter`, а не root. После перезагрузки сервера она
стартует сама. Поиск после перезапуска **не возобновляется автоматически**:
зайдите в панель и запустите его вручную. Найденные реальные адреса остаются
в VK Cloud и в `data/state.json`.

## 5. Настроить HTTP через Nginx

На чистом сервере со штатной конфигурацией Nginx:

```bash
cd /opt/vkiphunter
cp scripts/nginx-vkiphunter.conf /etc/nginx/sites-available/vkiphunter
ln -s /etc/nginx/sites-available/vkiphunter /etc/nginx/sites-enabled/vkiphunter
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl enable --now nginx
systemctl reload nginx
curl -fsS http://127.0.0.1/healthz
```

Удаляется только ссылка на стандартный сайт. Если на сервере уже есть другие
сайты или другой `default_server`, согласуйте `listen` и `server_name`,
не удаляйте чужие конфигурации. Если ссылка `vkiphunter` уже существует,
проверьте её через `readlink` и не создавайте повторно.

## 6. Firewall и облачная security group

Для SSH на стандартном порту 22:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw enable
ufw status
```

**Если SSH использует другой порт**, сначала разрешите именно его
(`ufw allow ВАШ_SSH_ПОРТ/tcp`) и убедитесь, что правило есть, только затем
включайте UFW. Сохраните текущую SSH-сессию до проверки нового подключения.

В панели провайдера сервера откройте входящие TCP 22 (или ваш SSH-порт) и
TCP 80. Для HTTPS позже понадобится TCP 443. TCP 8080 снаружи не требуется.
Для закрытого доступа по туннелю из раздела 9 публичный порт 80 можно вообще
не открывать. Ограничивайте HTTP своим IP в firewall/security group, если
он нужен только вам.

В браузере откройте:

```text
http://IP_СЕРВЕРА
```

Введите `WEB_PASSWORD`. Страница должна показать панель с разделами «Обзор»,
«Настройки поиска», «Подключение», «Облако и ВМ».

## 7. Подключить VK Cloud

### Сначала проверить интерфейс без расхода облачных ресурсов

1. Откройте «Подключение» → «Симуляция без облака» → «Проверить и подключить».
2. Посмотрите настройки и запустите поиск.
3. Остановите поиск и дождитесь статуса «Остановлен» перед сменой подключения.

Симулятор создаёт только объекты в памяти процесса. Его сохранённые находки
в истории — демонстрационные; после перезапуска соответствующих ресурсов
в симуляторе не будет. Не используйте их для реальных ВМ. Для чистого старта
после демо, **до подключения реального облака**, остановите службу и
переименуйте только состояние демо:

```bash
systemctl stop vkiphunter-web
mv /opt/vkiphunter/data/state.json /opt/vkiphunter/data/demo-state.json
systemctl start vkiphunter-web
```

Не выполняйте этот сброс после реального поиска: состояние содержит список
защищённых найденных ресурсов.

### OpenRC / логин и пароль

1. Откройте нужный проект в VK Cloud и скачайте его OpenStack RC / OpenRC.
   Точное название пункта зависит от интерфейса VK Cloud.
2. В панели Hunter выберите «OpenRC / логин и пароль».
3. Вставьте содержимое файла в поле OpenRC. Файл разбирается как текст,
   shell-код на сервере не выполняется.
4. Введите пароль OpenStack/API. Подстановки вроде `$OS_PASSWORD` из OpenRC
   не выполняются, поэтому пароль обычно надо ввести отдельно.
5. Нажмите «Проверить и подключить».

Можно обойтись без OpenRC и заполнить вручную Auth URL, регион, логин, пароль,
Project ID (либо Project name) и User domain name. Берите точные значения из
OpenRC вашего проекта. Auth URL должен начинаться с `https://`.

### Application credential

Для долгой работы удобнее отдельные application credentials проекта:
выберите этот способ и укажите Auth URL, регион, credential ID и secret
(или вставьте OpenRC с этими полями). Права должны позволять операции Neutron
с сетями/портами/floating IP и, если нужны ВМ, операции Nova/Glance/Cinder.
Сначала можно проверить доступы штатными инструментами VK Cloud/OpenStack.

Приложение проверяет доступ и внешнюю сеть **до сохранения новых реквизитов**.
При ошибке старые доступы остаются. Новые сохраняются в
`data/credentials.json` с правами 0600, браузеру пароль/secret обратно не
отдаются. Файл не шифруется: защищайте доступ к серверу и резервным копиям.

Если проверка пишет, что нет сети `internet`, сначала сохраните правильное
имя или ID внешней сети в настройках, затем повторите подключение.

## 8. Настроить и использовать поиск

1. Откройте «Настройки поиска»: проверьте внешнюю сеть, способ выделения,
   целевые IPv4 CIDR и исключения. По умолчанию выбран порт во внешней сети.
2. Сохраните сеть, затем нажмите «Загрузить подсети и доступность».
   Выберите существующие пулы с нужными диапазонами, снова сохраните.
   После смены сети старый выбор подсетей автоматически очищается.
3. Начните с одного воркера и интервала 90 секунд. Больше воркеров требует
   больше квоты и может увеличивать расходы/нагрузку на API.
4. Нажмите «Запустить поиск». История, найденные адреса и счётчики обновляются
   каждые 3 секунды. Поиск продолжает работать при закрытии вкладки и выходе
   из панели.
5. «Остановить» завершает текущую попытку, затем останавливает цикл.
   Изменять настройки и подключение можно после полной остановки.

`409 No more IP addresses available` означает пустой пул: цикл ждёт и
повторяет. Ошибка квоты означает, что нужны свободная квота, освобождение
лишних ресурсов или меньше воркеров. Отсутствие целевого диапазона во всех
доступных пулах нельзя исправить ожиданием.

В «Облако и ВМ» можно:

- смотреть сети, доступность пулов, порты, floating IP и ВМ;
- освободить свои пробные ресурсы текущего способа по префиксу `<prefix>-`:
  найденные, подключённые и чужие ресурсы пропускаются;
- загрузить каталог флейворов, образов и SSH-ключей и создать ВМ на найденном
  внешнем порту; размер/тип диска берутся из настроек;
- привязать найденный floating IP к существующей ВМ.

Создание ВМ и привязка требуют подтверждения в интерфейсе. Создание может
занять до 30 минут. Не нажимайте повторно при потере соединения: сначала
проверьте список ВМ и порты в VK Cloud, операция могла завершиться.
Приложение не удаляет найденный порт при ошибке создания ВМ.
Security groups и firewall внутри созданной ВМ настраиваются отдельно.

Не очищайте `data/state.json`: он хранит защиту найденных адресов от уборки.
Префикс выбирайте уникальный для этого экземпляра и не используйте его
для сторонних ресурсов. Одновременно запускайте только один процесс с
одними файлами состояния/доступов. Несколько веб-процессов с одним STATE_FILE
блокируются файловым lock; старый Telegram-бот этот lock не использует.

## 9. Закрытый HTTP через SSH-туннель — без домена

Можно оставить приложение на `127.0.0.1:8080` и вообще не выставлять HTTP
в интернет. На **своём компьютере** выполните:

```bash
ssh -N -L 8080:127.0.0.1:8080 root@IP_СЕРВЕРА
```

Оставьте терминал открытым и зайдите на `http://127.0.0.1:8080` в браузере
своего компьютера. Соединение с сервером шифруется SSH, а `WEB_SECURE_COOKIE`
в этом варианте остаётся `false`. Если 8080 на компьютере занят, замените
первое число, например на `18080`, и откройте `http://127.0.0.1:18080`.

Nginx для такого доступа не нужен. Если уже настроили его, закройте входящий
TCP 80 в firewall и security group, сохранив разрешение SSH.

## 10. HTTPS с доменом (рекомендуется для публичного доступа)

Нужен домен с A-записью на IP сервера; AAAA используйте только если IPv6
действительно настроен. В `/etc/nginx/sites-available/vkiphunter` замените
`server_name _;` на `server_name hunter.example.com;` со своим доменом.

```bash
nginx -t
systemctl reload nginx
apt install -y certbot python3-certbot-nginx
ufw allow 443/tcp
certbot --nginx -d hunter.example.com --redirect
```

Откройте 443 и в security group. После успешного выпуска сертификата:

```bash
sed -i 's/^WEB_SECURE_COOKIE=.*/WEB_SECURE_COOKIE=true/' /opt/vkiphunter/.env
systemctl restart vkiphunter-web
certbot renew --dry-run
```

Используйте только `https://hunter.example.com`. При Secure cookie вход через
обычный HTTP/IP работать не будет. Установка certbot создаёт механизм
автопродления; проверьте `systemctl list-timers --all | grep certbot`.

## 11. Обновление и резервные копии

Перед обновлением остановите поиск из панели, затем службу. Остановка может
ждать завершения текущего облачного запроса; не убивайте процесс без нужды.
Резервная копия содержит пароль облака — храните её закрыто.

```bash
systemctl stop vkiphunter-web
install -d -m 0700 /root/vkiphunter-backups
tar -czf "/root/vkiphunter-backups/vkiphunter-$(date +%Y%m%d-%H%M%S).tgz" -C /opt/vkiphunter data .env
chmod 0600 /root/vkiphunter-backups/*.tgz
cd /opt/vkiphunter
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt
cp scripts/vkiphunter-web.service /etc/systemd/system/
systemctl daemon-reload
systemctl start vkiphunter-web
curl -fsS http://127.0.0.1:8080/healthz
```

Конфигурацию Nginx при обновлении сравнивайте вручную: не затирайте правки
домена и HTTPS. Если после слияния переходите на основную ветку:

```bash
git fetch origin
git switch claude/new-project-fd3wg2
git pull --ff-only
```

Если имя основной ветки в репозитории изменится, используйте её актуальное
имя. Переход делайте при остановленной службе, после резервного копирования.

Для восстановления на том же или новом сервере: остановите службу,
распакуйте выбранный архив в `/opt/vkiphunter`, восстановите владельцев и права,
затем запустите службу. Пример для заранее выбранного файла `backup.tgz`:

```bash
systemctl stop vkiphunter-web
tar -xzf /root/backup.tgz -C /opt/vkiphunter
chown -R vkiphunter:vkiphunter /opt/vkiphunter/data
chmod 0700 /opt/vkiphunter/data
chmod 0600 /opt/vkiphunter/data/credentials.json
chown root:vkiphunter /opt/vkiphunter/.env
chmod 0640 /opt/vkiphunter/.env
systemctl start vkiphunter-web
```

Файл credentials.json появляется только после первого сохранённого
подключения; если его ещё нет, соответствующую команду chmod пропустите.
Архивы восстанавливайте только свои, из доверенного источника.

## 12. Перенос с Telegram-бота

Если бот уже установлен:

1. Остановите поиск в боте и `systemctl disable --now vkiphunter`.
   Если использовали супервизор: `./scripts/vkiphunterctl stop`.
2. Сделайте резервную копию `data/` и `.env`.
3. Получите ветку веб-версии, обновите зависимости и добавьте WEB_* в `.env`.
   Не выполняйте генератор нового `.env` поверх старого.
4. Убедитесь, что `.env` читается службой и `data/` принадлежит `vkiphunter`.
   Для старых файлов: `chown -R vkiphunter:vkiphunter /opt/vkiphunter/data`.
5. Установите новую службу и Nginx по разделам 4–5.

Настройки и найденные ресурсы используют тот же формат JSON; доступы из
старого `data/credentials.json` подхватятся. BOT_TOKEN можно убрать из `.env`.
Облачные переменные OS_* остаются запасным источником доступа: чтобы кнопка
«Забыть подключение» действительно отключала облако, удалите OS_* и SIMULATE
из окружения/.env и перезапустите службу.

Старая инструкция Telegram-версии: [INSTALL-TELEGRAM.md](INSTALL-TELEGRAM.md).

## 13. Диагностика

| Симптом | Что проверить |
| --- | --- |
| 502 от Nginx | `systemctl status vkiphunter-web`, затем `journalctl -u vkiphunter-web -n 100`; `curl http://127.0.0.1:8080/healthz` |
| IP не открывается | входящие 80/443 в UFW и security group; `ss -ltnp`, `nginx -t` |
| Служба падает сразу | WEB_PASSWORD минимум 16 символов; права на `.env` и `data/`; установка requirements в `.venv` |
| «Другой веб-процесс» | уже запущен экземпляр с тем же STATE_FILE; остановите лишний процесс, не удаляйте lock у работающей службы |
| Не пускает после включения Secure cookie | открывайте HTTPS с доменом; для HTTP нужно WEB_SECURE_COOKIE=false и перезапуск |
| «Слишком много попыток» | подождите минуту; за Nginx лимит действует суммарно для соединений через локальный прокси |
| Облако не подключается | Auth URL/регион из вашего OpenRC, верный API-пароль или application secret, проект и права; доступ сервера к API |
| 409 о выполняемой операции | дождитесь завершения текущего запроса; состояние панели продолжает обновляться |
| Нет нужных адресов | смотрите подсети и доступность; CIDR должен существовать среди доступных пулов |
| Тайм-аут при создании ВМ | сначала проверьте Nova и порты в облаке; ВМ могла создаться, адрес не удаляйте |

Лог приложения: `/opt/vkiphunter/data/vkiphunter.log` (ротация по 5 МБ),
последние строки также доступны в разделе «Обзор». Не включайте DEBUG
на публичном сервере без необходимости: SDK может писать тела облачных
запросов. Редактирование интерфейсом не меняет LOG_LEVEL.

Для локальной разработки и проверок:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты не используют реальный VK Cloud и не создают платные ресурсы.
