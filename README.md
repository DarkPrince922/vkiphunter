# VK IP Hunter

Telegram-бот, который перебирает публичные IPv4 в VK Cloud и останавливается,
когда облако выдаст адрес из нужного диапазона.

Метод тот же, что и в исходном `wait-direct-ip.sh`: в внешней сети
`internet` создаётся **один** OpenStack-порт, VK Cloud назначает ему свободный
публичный адрес, адрес проверяется по CIDR — неподходящий порт удаляется,
подходящий сохраняется и становится сетевым интерфейсом новой ВМ.

```
создать порт → получить IPv4 → проверить CIDR
     ├─ не подходит → удалить порт → пауза 90 с → повтор
     └─ подходит    → порт сохранить, охоту остановить, создать ВМ
```

Это не сканирование чужих адресов и не перезапуск существующей ВМ: бот
работает только с ресурсами вашего проекта через штатный OpenStack API.

## Что умеет

* Полное управление из Telegram — консоль и `tmux` больше не нужны.
* Живое сообщение статуса, которое обновляется на каждой попытке, плюс
  сводка раз в N попыток и мгновенное уведомление о находке.
* Проверка адреса математикой `ipaddress`, а не сравнением строк:
  `217.16.200.1` не пройдёт как «похожий на 217.16.».
* Ошибка `409 No more IP addresses available` считается штатной — цикл
  ждёт и повторяет, ничего не пересоздавая.
* Найденный порт не удаляется никогда: ни при остановке, ни при ошибке
  создания ВМ, ни при массовой уборке.
* Удаляются только свои probe-порты (по префиксу имени). Чужие порты сети
  `internet` бот не трогает ни при каких обстоятельствах.
* Мастер создания ВМ: флейвор → образ → ключ → подтверждение, с фильтрами
  по историческим параметрам (1 vCPU, 2 ГБ, Ubuntu 24.04, диск 10 ГБ).
* Правка всех параметров прямо в боте: интервал, сеть, префикс, тайм-ауты,
  лимит попыток, целевые диапазоны и исключения.
* Режим симуляции — можно пощупать бота без облачного проекта.

## Установка

```bash
git clone <repo> /opt/vkiphunter
cd /opt/vkiphunter
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
```

В `.env` обязательны две вещи: `BOT_TOKEN` от [@BotFather](https://t.me/BotFather)
и `ALLOWED_USER_IDS` — Telegram-ID тех, кому можно управлять ботом. Свой ID
покажет команда `/whoami` (бот ответит им даже тому, кого не пустил).

### Доступ к VK Cloud

Вариант 1 — запускать с OpenRC-файлом проекта:

```bash
./scripts/run.sh /root/mcs6434280924-openrc.sh
```

Вариант 2 (лучше для постоянной работы) — application credential, он не
зависит от смены пароля аккаунта:

```bash
source /root/mcs6434280924-openrc.sh
openstack application credential create vkiphunter
```

Полученные `id` и `secret` положить в `.env` как
`OS_APPLICATION_CREDENTIAL_ID` и `OS_APPLICATION_CREDENTIAL_SECRET`.

### Запуск

```bash
.venv/bin/python -m vkiphunter          # креды из .env / окружения
./scripts/run.sh /path/to/openrc.sh     # креды из OpenRC
```

Как сервис:

```bash
cp scripts/vkiphunter.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now vkiphunter
```

Проверить бота без облака:

```bash
SIMULATE=1 BOT_TOKEN=... ALLOWED_USER_IDS=... .venv/bin/python -m vkiphunter
```

## Команды

| Команда | Что делает |
| --- | --- |
| `/menu` | главное меню с кнопками |
| `/hunt` | запустить охоту (сначала проверяет доступ к облаку) |
| `/stop` | остановить после текущей попытки |
| `/status` | попытки, 409, ошибки, время работы, следующая попытка |
| `/history` | последние 20 попыток с адресами и причинами |
| `/ips` | какие адреса уже выдавались и сколько раз |
| `/ports` | порты сети `internet`: свои probe-порты отдельно от чужих |
| `/cleanup` | удалить свои probe-порты (найденные и подключённые к ВМ не тронет) |
| `/vm` | создать ВМ на найденном порту |
| `/settings` | интервал, сеть, префикс, тайм-ауты, лимит, диск |
| `/targets` | целевые диапазоны и исключения |
| `/cloud` | проверить авторизацию и наличие внешней сети |
| `/whoami` | свой Telegram ID |

## Целевые диапазоны

По умолчанию — те же, что в исходном watcher-скрипте:

```
5.188.140.0/22
217.16.16.0/21
217.16.24.0/22
217.16.28.0/22
```

Три сети `217.16.*` вместе покрывают `217.16.16.0/20`, куда входил рабочий
адрес `217.16.22.90`. Списки правятся в `/targets`; исключения приоритетнее
целей, так что отбракованный подсегмент можно вырезать, не трогая цель.

## Что бот не делает

Попадание в CIDR — только предварительный фильтр. Он **не** доказывает, что
мобильный оператор пропускает адрес. Реальная проверка остаётся ручной:

1. подключить найденный порт к ВМ;
2. открыть нужный порт в security group и в firewall самой машины;
3. поднять health-endpoint и убедиться, что он отвечает из обычного интернета;
4. на телефоне выключить Wi-Fi и повторить запрос через целевую SIM/APN.

| Обычный интернет | Ограниченная сеть | Вывод |
| --- | --- | --- |
| не работает | не работает | чинить сервер, firewall или security group |
| работает | не работает | адрес не проходит белый список оператора |
| работает | работает | адрес — рабочий кандидат для этой SIM/APN на момент теста |

`whois`, ASN, PTR и принадлежность облаку сетевой тест не заменяют.

## Ограничения

* Нужный пул может больше не участвовать в новых выдачах.
* Один и тот же адрес может выдаваться повторно — счётчик в `/ips` это покажет.
* `409` может держаться долго; это состояние пула, а не поломка проекта.
* VK Cloud может изменить имя внешней сети, квоты или правила подключения
  прямого внешнего порта — имя сети меняется в `/settings`.
* Созданные порты и ВМ влияют на квоты и тарификацию.
* После перезапуска бота охота не возобновляется сама — он об этом напишет.

## Разработка

```bash
.venv/bin/pip install pytest pytest-asyncio
.venv/bin/python -m pytest
```

Тесты гоняют движок на сценарном облаке и весь бот целиком на замоканном
Telegram API — сеть при этом не используется.

```
vkiphunter/
├── cidr.py          проверка адреса по CIDR
├── state.py         настройки, статистика, найденные порты (JSON на диске)
├── hunter.py        цикл охоты
├── config.py        переменные окружения / OpenRC
├── cloud/           openstacksdk и симулятор
└── bot/             aiogram: хендлеры, клавиатуры, уведомления
```
